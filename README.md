# FSM DSL and Code Generator for Rust (`.ssot`)

This project provides a Domain Specific Language (DSL) inspired by Cap'n Proto for defining Finite State Machines (FSMs) and tools to generate type-safe Rust code from these definitions. The `.ssot` extension signifies the **Single Source of Truth** for the state machine specification.

## Background

The core idea is to leverage a dedicated DSL (`.ssot`) for declaratively defining FSMs. This approach aims to:

*   **Model Intuitively:** Represent states (basic, composite, parallel, historical), events, and transitions clearly.
*   **Ensure Type Safety:** Automatically generate Rust code (bindings) that enforces the state machine rules at compile time.
*   **Improve Efficiency:** Utilize a syntax designed for potentially zero-copy parsing and minimal binary size overhead, similar to Cap'n Proto's principles (though the current implementation uses `pest`).
*   **Centralize Specification:** Use the `.ssot` file as the definitive source for the FSM's logic, from which code, documentation, and potentially other artifacts (like diagrams or schemas) can be derived.

## Project Goal

The primary goal is to enable developers to define state machine logic declaratively in a `.ssot` file and automatically generate the necessary Rust boilerplate code, ensuring type safety and reducing manual implementation effort.

## Workspace Structure

This project is organized as a Cargo workspace containing the following crates:

*   `crates/fsm-dsl`: Defines the `.ssot` grammar (`ssot.pest`), the Abstract Syntax Tree (`ast.rs`), and the parser logic (`parser.rs`) using the `pest` library.
*   `crates/fsm-codegen`: Takes the AST generated by `fsm-dsl` and generates corresponding Rust code (`lib.rs`), including state enums, event types, and transition functions, utilizing `syn`, `quote`, and `prettyplease`.
*   `crates/fsm-example`: A demonstration crate showing how to use the DSL. It includes a sample `spec/my_fsm.ssot` file and utilizes a `build.rs` script to invoke the parser and code generator during the build process.

## Usage (Example)

1.  Navigate to the workspace root directory (`ssot/`).
2.  Run `cargo build`. This command will:
    *   Build the `fsm-dsl` and `fsm-codegen` crates.
    *   Execute the `build.rs` script within `fsm-example`, which parses `spec/my_fsm.ssot` and generates Rust code (likely into the `target` directory or a specific `OUT_DIR`).
    *   Compile the `fsm-example` crate, linking against the generated code.

*(Note: Examine the `fsm-example/src/lib.rs` and `fsm-example/build.rs` for details on how the generated code is integrated and used.)*

## Current Status

The foundational components for parsing the `.ssot` DSL and generating basic Rust FSM structures are implemented. The `fsm-example` demonstrates the build-time code generation workflow.

## Roadmap / Future Enhancements

*   **Enhanced Code Generation:**
    *   Generate placeholder or skeleton functions for defined `guard` and `action` attributes.
    *   Explore generating visualization outputs (e.g., Mermaid syntax, Graphviz DOT).
    *   Investigate support for hierarchical state machines.
*   **Improved DSL Features:**
    *   Add syntax for entry/exit actions on states.
    *   Enhance validation rules within the parser.
*   **Error Handling:** Improve error messages and diagnostics from the parser and code generator.
*   **Testing:** Develop more comprehensive automated tests for the `fsm-dsl` and `fsm-codegen` crates.
*   **Procedural Macro:** Implement the `#[state_machine(...)]` procedural macro approach as an alternative integration method.
